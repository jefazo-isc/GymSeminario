Introducción

Contexto y Diagnóstico

Problemática en Centros Deportivos

En México, los gimnasios independientes suelen administrarse mediante procesos analógicos y descentralizados (libretas en papel, hojas de cálculo sin sincronización y validación visual en torniquetes). Esta dinámica genera fugas de ingresos de hasta un 25% por cobros extemporáneos no auditados, duplicidad de socios y suplantación en accesos.

Asimismo, la falta de planes de entrenamiento individualizados ocasiona una tasa de abandono superior al 35% durante los primeros 90 días, perjudicando gravemente la sostenibilidad del negocio.

Propuesta de Solución: espacioGYM (GROM 21)

Se diseñó e implementó espacioGYM, una Progressive Web App (PWA) reactiva basada en Angular 19.2, backend modular en Node.js/Express, persistencia ligera con SQLite 3 en modo WAL (Write-Ahead Logging) y un motor dual de Inteligencia Artificial para prescripción de rutinas dinámicas mediante Gemini API y fallback local.

Objetivos

Alcance y Metas

Objetivo General

Diseñar, implementar, evaluar y desplegar en producción una plataforma web progresiva (espacioGYM) articulada con metodologías ágiles (Scrum) y prácticas de ingeniería continua (DevOps), optimizando la gestión de membresías, el control de acceso por QR dinámico y la generación de rutinas mediante IA.

Objetivos Específicos

1
Framework Ágil y Gobernanza (Meso): Adaptar Scrum a 8 Sprints de dos semanas, vinculando la Definition of Done (DoD) a la aprobación estricta de pruebas automatizadas.
2
Pipeline CI/CD Automatizado (Micro): Configurar GitHub Actions y Docker multi-etapa para compilar y ejecutar pruebas unitarias con cobertura > 80% y despliegue continuo en < 4 min.
3
Persistencia Ligera y Concurrente: Integrar SQLite con WAL y transacciones ACID atómicas, logrando latencias < 150 ms sin costo de hosting dedicado.
4
Terminales de Acceso por QR y Motor IA: Validar el control de asistencia en tiempo real mediante QR seguros y la prescripción adaptativa de ejercicios con Gemini API.

Materiales y Métodos

Meso y Micro

Marco Metodológico Híbrido (Nivel Meso)

Se implementó un modelo híbrido Scrum-DevOps organizado en 8 Sprints de 2 semanas. La gobernanza técnica se distribuyó en 3 roles clave (Product Owner: Tapia, Scrum Master: Padilla, Lead Developer: Guevara). La priorización se gestionó bajo la técnica MoSCoW (14 Must Have, 8 Should Have), asegurando trazabilidad integral del Product Backlog.

A diferencia de Scrum tradicional, la Definición de Terminado (DoD) se vinculó obligatoriamente a compuertas de CI/CD: ningún incremento se integró a la rama main sin pruebas unitarias aprobadas y análisis de vulnerabilidades en cero.

Stack Tecnológico Micro e Infraestructura

Angular 19.2 TypeScript 5.6 Tailwind CSS Node.js 22 LTS Express REST SQLite 3 (WAL) Docker Multi-Stage GitHub Actions Karma / Jasmine Gemini Dual IA

PRAGMA journal_mode = WAL;

Dockerfile Multi-Etapa (Optimización 198 MB)
FROM node:20-alpine AS build
COPY . /app && RUN npm ci && npm run build --prod
FROM nginx:alpine-slim
COPY --from=build /app/dist/espacio-gym /usr/share/nginx/html

Arquitectura Resiliente: El modo WAL permite lecturas concurrentes sin bloquear escrituras, manteniendo latencias < 120 ms bajo concurrencia continua.

Conclusiones

Síntesis y Aportes

Trazabilidad Meso-Micro Demostrada

Se demostró empíricamente que la articulación entre el Nivel Meso (acuerdos de proceso, DoD y flujo DevOps) y el Nivel Micro (código Angular 19, SQLite WAL y suites de pruebas automatizadas) erradica regresiones en producción y dota al proyecto de total trazabilidad técnica y metodológica.

Eficiencia y Sostenibilidad Económica

La arquitectura basada en componentes ligeros comprobó que los centros deportivos medianos pueden operar con alta concurrencia y tiempos de respuesta de sub-segundo (< 120 ms) con costos de infraestructura prácticamente nulos, haciendo viable la adopción tecnológica en PYMEs.

Aportes Principales de la Investigación

1. Puente Metodológico: Correspondencia formal entre eventos Scrum y compuertas CI/CD ejecutables.
2. Persistencia Ligera: Demostración de viabilidad técnica de SQLite WAL para aplicaciones web comerciales concurrentes.
3. Validación Integral: Plataforma desplegada y validada funcionalmente al 100% (Apartado 4.7.2).

Aprobación Institucional: Proyecto listo para sustentación pública y entrega final ante el comité evaluador del Centro de Ciencias Básicas de la Universidad Autónoma de Aguascalientes.
